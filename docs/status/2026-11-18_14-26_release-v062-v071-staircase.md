## e) What could be better

- The parity-gate/sync-gate failures were both _policy-vs-reality drift encoded in gates_: gates written in one context (post-release, patch-anchored) that silently inverted the intended semantics later. A cheap improvement: each gate check that encodes a POLICY should cite its owner-decision date in a comment (done for the two fixed here; not yet a repo-wide convention).
- The staircase's per-step CI waits were serialized with sleeps; a small `scripts/staircase.sh` helper (tag → push → watch frozen run → next) would remove the manual latency and the quoting-bug class entirely.
- The v0.7.0 anomaly (root-only tag, no CHANGELOG section, failed release.yml, manual pre-release page) went uninvestigated for two weeks. A post-release checklist item "verify release.yml ran green" after every root tag would have caught it same-day.
