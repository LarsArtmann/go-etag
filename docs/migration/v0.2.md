# Migration Guide: v0.1 → v0.2

The v0.2 release introduces a dedicated `ETag` type, a `Strength` enum, and several
configuration improvements. This guide covers every breaking change with before/after
code examples.

---

## 1. Constructor renamed: `ETag()` → `New()`

The old `ETag()` function name collided with the new `ETag` type.

**Before:**

```go
handler := etag.ETag(etag.DefaultETagConfig())
```

**After:**

```go
handler := etag.New(etag.DefaultETagConfig())
```

---

## 2. `Weak bool` → `Strength Strength`

The boolean `Weak` field is replaced by the `Strength` enum (`Strong` / `Weak`), which
uses RFC 7232 vocabulary and prevents accidentally producing weak validators.

**Before:**

```go
cfg := etag.ETagConfig{
    Weak:          true,
    MaxBufferSize: 2 * 1024 * 1024,
}
```

**After:**

```go
cfg := etag.ETagConfig{
    Strength:      etag.Weak,
    MaxBufferSize: 2 * 1024 * 1024,
}
```

`DefaultETagConfig()` already sets `Strength: Strong`.

---

## 3. `HashFunc` signature changed

The hash function now returns the opaque tag value as a `string` (the unquoted content
that goes between the double quotes), not a raw `uint64`. This allows arbitrary hash
algorithms (SHA-256, xxHash, database revision numbers, etc.).

**Before:**

```go
cfg := etag.ETagConfig{
    HashFunc: func(data []byte) uint64 {
        h := sha256.Sum256(data)
        return binary.BigEndian.Uint64(h[:8])
    },
}
```

**After:**

```go
cfg := etag.ETagConfig{
    HashFunc: func(data []byte) string {
        h := sha256.Sum256(data)
        return hex.EncodeToString(h[:]) // full 256-bit hash as opaque tag
    },
}
```

If you used `DefaultETagConfig().HashFunc` (FNV-64a), no change is needed — the default
is updated automatically.

---

## 4. New `ETag` type and helpers

v0.2 introduces a first-class `ETag` type with RFC 7232 §2.3.2 comparison functions.
These are optional — the middleware works the same as before — but enable manual
conditional-request handling in your handlers.

```go
// Parse a client-sent If-Match header and evaluate strong comparison.
tag := etag.NewETag("abc123-rev42", etag.Strong)

if etag.MatchesIfMatch(tag, req.Header.Get("If-Match")) {
    // Safe to apply the update.
} else {
    w.WriteHeader(http.StatusPreconditionFailed)
    return
}
```

Available helpers:

| Function                              | Comparison | Use case                          |
| ------------------------------------- | ---------- | --------------------------------- |
| `etag.MatchesIfNoneMatch(tag, header)` | Weak       | Cache validation (304 Not Modified) |
| `etag.MatchesIfMatch(tag, header)`     | Strong     | Lost-update prevention (412)       |
| `etag.ParseETag(s)`                    | —          | Parse one entity-tag from wire format |
| `etag.ParseETagList(header)`           | —          | Parse comma-separated tag list      |

---

## 5. New config fields

Three optional fields were added. All default to zero values and require no code changes:

| Field            | Type                          | Purpose                                                    |
| ---------------- | ----------------------------- | ---------------------------------------------------------- |
| `SkipIfPresent`  | `bool`                        | Respect an ETag header already set by the handler          |
| `Skip`           | `func(*http.Request) bool`    | Per-request opt-out (streaming endpoints, SSE, etc.)       |
| `OnError`        | `func(*errorfamily.Error)`    | Observability hook for post-commit write failures          |

---

## 6. Bug fixes that may change behavior

Three RFC compliance bugs were fixed. If your tests relied on the old (incorrect)
behavior, update them:

| Bug | Old behavior | Fixed behavior |
| --- | --- | --- |
| HEAD body | Middleware forwarded the response body on HEAD requests | Sets `Content-Length` and sends no body (RFC 7230 §3.3) |
| 304 Content-Length | `Content-Length` header leaked into 304 responses | Stripped before sending 304 (RFC 7232 §4.1) |
| Zero-value config | `ETagConfig{}` caused unbounded buffering | `MaxBufferSize` clamped to 1 MB default |

---

## Quick reference: full migration

```go
// v0.1
handler := etag.ETag(etag.ETagConfig{
    Weak:          false,
    MaxBufferSize: 1024 * 1024,
})

// v0.2
handler := etag.New(etag.ETagConfig{
    Strength:      etag.Strong,
    MaxBufferSize: 1024 * 1024,
})
```
